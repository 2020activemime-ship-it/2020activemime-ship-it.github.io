SETUP GUIDE

自動投稿を、はじめましょう

このたびはご購入いただき、ありがとうございます。
このページの順番どおりに進めれば、はじめの設定が終わります。レクチャー動画も、このページと同じ順番で進みます。

終わったところは「できた」を押してください。途中でページを閉じても、進み具合は残ります。

所要時間 15〜30分パソコンでの作業がおすすめプログラミングの知識は不要
0 / 0 完了

はじめに、ご購入のプランを選んでください

プランに合わせて、必要な手順だけが表示されます。

大切なお願い　このあと発行する「鍵」（キー・トークン）は、販売者を含め、誰にも送らないでください。あなたのGitHubの中にだけ貼り付けます。レクチャー動画の中でも、鍵の文字は映していません。
1

GitHubに登録する

約3分｜すでにアカウントがある方は「できた」を押して次へ

自動投稿の仕組みを置いておく場所です。無料で使えます。

  1. 下のボタンからGitHubを開いて、「Sign up」を押す
  2. メールアドレス・パスワード・ユーザー名を決める
  3. 届いたメールのコードを入力する
  4. 決めたユーザー名を、下の欄に入れる（すでにアカウントがある方も入れてください）
GitHubを開く

GitHubの画面右上の丸いアイコンを押すと、太字で出ている名前です。ここに入れると、このあとの「この画面を開く」ボタンが、あなたの画面に直接つながります。入れた内容は、このパソコンの中にだけ保存されます。

2

仕組みを、自分の場所にコピーする

約2分

納品メールのあと、GitHubから「招待」のメールが届きます。

  1. 招待メールの「View invitation」→「Accept invitation」を押す（下のボタンからでも開けます）
  2. 開いたページの右上、緑の 「Use this template」→「Create a new repository」 を押す
  3. Repository name に名前を入れる（例：my-autopost）
  4. Private（非公開）を選んで「Create repository」
  5. Public（公開）を選んで「Create repository」
    Instagramは、ネット上から見える画像しか投稿できないためです。投稿の文章や鍵は見えません。
招待を承認する コピーを作る画面を開く

上の3番で入れた名前を、同じように入れてください。

3

書き込みを許可する

約1分｜ここを忘れると、投稿の記録が残りません
  1. 下のボタンで設定画面を開く
  2. いちばん下の Workflow permissions を 「Read and write permissions」 に変える
  3. 「Save」を押す
この画面を開く

手順1のユーザー名と、手順2の名前を入れると押せるようになります。

4

Xの鍵を4つ発行する

約7分｜いちばんつまずきやすい手順です。ゆっくりで大丈夫です
  1. 下のボタンでXの開発者ページを開き、いつものXアカウントでログイン
  2. 「Projects & Apps」でアプリを作る（名前は何でもOK）
  3. Settings → User authentication settings を開き、次のとおりに入れて保存
    項目入れるもの
    App permissionsRead and Write
    Type of AppWeb App, Automated App or Bot
    Callback URIhttps://example.com/callback
    Website URLあなたのSNSやブログのURL
  4. 「Keys and tokens」のタブで、次の4つを発行してメモ帳に控える
    API Key ／ API Key Secret ／ Access Token ／ Access Token Secret
  5. 開発者ページで、利用料を少しだけ入金しておく
いちばん多いつまずき　権限を「Read and Write」に変えたあとで、Access Token を作り直してください。変える前に作ったトークンのままだと、投稿のときに 403 Forbidden になります。
利用料の目安　Xは1本ごとにかかります。リンクなし約2円、リンクあり約30円。1日5本で月300〜500円ほどです。残高がなくなると 402 と出て止まります。
Xの開発者ページを開く
5

Threadsの鍵を発行する

約5分｜Facebookのアカウントが要ります（Facebookには投稿しません）
  1. 下のボタンでMetaの開発者ページを開いてログイン
  2. 「アプリを作成」→ 用途で Threads API を選ぶ
  3. 「役割」→「Threadsテスター」に、あなたのThreadsアカウントを追加
  4. スマホのThreadsアプリで、設定 → アカウント → ウェブサイトのアクセス許可 → 招待 を開いて承認
  5. 開発者ページに戻り、アクセストークンを発行してメモ帳に控える
60日で切れます　Threadsの鍵には期限があります。60日たったら、同じ手順で作り直して貼り替えてください。カレンダーに入れておくと安心です。
Metaの開発者ページを開く
6

Instagramの鍵と、画像の置き場所

約5分｜プランB・Cの方
  1. Instagramアプリで、プロアカウント（ビジネス／クリエイター）に切り替える（無料）
  2. 手順5と同じMetaのアプリに Instagram を追加して、アクセストークンを発行する
  3. 画像を置く場所をつくる：下のボタンで設定を開き、Source を Deploy from a branch、Branch を main ／ (root) にして「Save」
  4. 数分待つ。あなたの画像の置き場所は、次のURLになります 
    https://（ユーザー名）.github.io/（置き場所の名前）/images
画像の置き場所の設定を開く
7

鍵を貼り付ける

約5分｜1つずつ「名前」と「中身」を入れて保存します
  1. 下のボタンで、鍵を入れる画面を開く
  2. Name に下の表の「名前」をコピーして貼る。Secret に中身を貼る
  3. 「Add secret」で保存。これを表の行の数だけくり返す（貼ったら表にチェック）
鍵を入れる画面を開く

8

投稿せずに、動くか確かめる

約3分｜鍵が正しいかだけを確認します
  1. 下のボタンで「autopost」の画面を開く
  2. 右の 「Run workflow」 を押す。dry_run は 1、watch は 0 のまま、緑の「Run workflow」
  3. 1分ほどで一覧に結果が出ます。いちばん上を開いて「watch and post」の中を見る

こう出ていれば成功です。

NG と出たら、ページ下の「うまくいかないとき」を見てください。

autopostの画面を開く
9

投稿の中身を確かめる

約5分｜お作りした投稿が入っています

ヒアリングをもとにお作りした投稿は、schedule.json に日時つきで入っています。

  1. 下のボタンで中身を開く
  2. 直したいところがあれば、右上の鉛筆マークで書き換えて「Commit changes」
  3. "at" が投稿する日時（日本時間）、"text" が文章です。記号の " や , は消さないようにしてください
書き換えに自信がないときは、直したい文章をメールで送っていただければ、30日間はこちらで差し替えます。
投稿の中身を開く
10

自動投稿を、スタートする

約1分｜これで最後です
  1. 手順8と同じ画面で、もう一度 「Run workflow」
  2. 今度は dry_run を 0、watch を 1 にして実行
  3. 黄色い丸が回っていれば、見張りが始まっています。そのままページを閉じて大丈夫です

このあとは、毎朝4時から夜23時まで自動で見張り、決めた時間になったら投稿します。パソコンを閉じていても動きます。あなたがやることは、もうありません。

autopostの画面を開く
COMPLETE

おつかれさまでした

設定はすべて終わりです。はじめの投稿が出たら、SNSで見てみてください。
ここからは、仕組みが毎日かわりに働きます。

うまくいかないとき

Xだけ失敗する403 Forbidden

権限が「Read」のままか、権限を変えたあとでAccess Tokenを作り直していません。手順4の最後をやり直して、手順7で X_ACCESS_TOKEN と X_ACCESS_SECRET を貼り替えてください（同じ名前で作ると上書きされます）。

Xが止まった402

Xの利用料の残高がなくなっています。Xの開発者ページで入金すると、次の投稿から再開します。

鍵が通らないInvalid OAuth access token

鍵の前後に空白が入っているか、期限が切れています。Threadsは60日で切れます。一度消して、貼り直してください。

Instagramだけ失敗する

プロアカウントになっているか、手順6の画像の置き場所が設定されているか、置き場所がPublic（公開）になっているかを確かめてください。

投稿の記録が残らない／同じ投稿が何度も出そうになる

手順3の「Read and write permissions」が保存されているか確かめてください。

決めた時間に出ない

GitHubの混み具合で、数分〜十数分遅れることがあります。1時間以上出ないときは、手順10の画面で黄色い丸（見張り）が動いているか見てください。止まっていたら、手順10をもう一度。

それでも直らない

autopostの画面で失敗した回（赤いバツ）を開き、赤い行をそのままコピーして、納品メールに返信してください。鍵そのものは送らないでください。30日間、1〜3営業日以内にお返事します。
